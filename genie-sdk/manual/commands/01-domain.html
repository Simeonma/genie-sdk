f.domain — physical domain & boundaries

Domain size (per-axis ranges), total time, CFL, and boundary conditions on the six faces. All SI. Property assignments write straight to the config.

#f.domain properties

PropertyType / unitRequiredDescription
x_range / y_range / z_range(lo, hi) 2-tuple, mYesPhysical domain extent per axis, lo < hi (guarded server-side by _check_range). The wire format defines no default; an unset range is an error, not a fallback
total_times, > 0YesTotal simulated time — the single definition of simulation length; the wire format defines no default and requires total_time > 0. At build the server derives the step count from it via dt (a read-only value reported in summary/results; there is no run.n_steps)
cflfloat, default 0.9, 0 < cfl ≤ 1Fraction of the stability limit dt uses; leave alone, lowering buys stability margin at the cost of more steps
f.domain.x_range = (-1e-6, 1e-6)
f.domain.y_range = (-1e-6, 1e-6)
f.domain.z_range = (-2e-6, 2e-6)
Common pitfalls
  • Reversed range (hi, lo) is rejected at submit time; a single number instead of a 2-tuple raises TypeError or yields a silently wrong value (the setter indexes v[0]/v[1] directly).

#f.domain.boundary_condition()

Set a boundary condition on one of the six faces; each face is set independently and unset faces default to pec (the kernel fills every unset face with pec; see api/domain.py:103). Returns: Domain (itself, chainable).

ParamTypeRequiredDefaultDescription
facestrYes—x_min / x_max / y_min / y_max / z_min / z_max
kindstrYes—pec / pmc / periodic / pml / bloch
layersintNo12pml only: PML (perfectly matched layer — an absorbing termination that suppresses reflections at the domain edge) layers (≥ 2)
kappa_maxfloatNo1.0pml only: max absorption coefficient (≥ 1.0)
orderintNo3pml only: polynomial order (≥ 1)
k(kx, ky, kz)No—bloch only: Bloch wave vector (rad/m)
from_sourceboolNo—bloch only: True = wave vector taken automatically from in-plane sources
n_backgroundfloatNounsetbloch only: background refractive index (> 0). The wire format leaves it unset (None) and the kernel takes 1.0 (builder.py:114); the Bloch k scales as nbackground · (2πf₀/c) · k̂
Example
f.domain.boundary_condition('z_min', 'pml')
f.domain.boundary_condition('z_max', 'pml', layers=16)
f.domain.boundary_condition('x_min', 'periodic')
f.domain.boundary_condition('y_min', 'bloch', k=(1e7, 0, 0))
Common pitfalls
  • periodic and bloch must be set as a same-axis pair (both x_min and x_max, etc.); the wire format enforces pairwise consistency (_wire.py pair validator) and a submission with only one face of the pair set is rejected with 422. pec/pmc carry no pairing requirement.
  • pml cannot be mixed with periodic/bloch on the same axis: a face with pml opposite a face with periodic (or bloch) is rejected as an error.
  • Unset faces default to pec — a perfectly reflecting cavity wall. In transmission-measurement setups, do not rely on the default faces; set absorbing boundaries explicitly on every face light can reach.
  • Oblique-incidence periodic simulations need bloch, not periodic (otherwise diffraction-order phases are wrong).
  • Both the entrance and exit faces need absorbing boundaries (e.g. light from x_min → PML on both x faces), or reflections contaminate monitor readings.
  • Misspelled pml/bloch keyword arguments (e.g. layer) are silently ignored and fall back to defaults; invalid face/kind values raise ValueError immediately.
